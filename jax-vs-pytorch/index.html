How JAX and PyTorch run your code

JAX and PyTorch both run Python array programs on accelerators. JAX can execute individual operations directly, while transformations such as jit trace a function into an intermediate program that XLA compiles. PyTorch runs tensor operations eagerly by default and can capture regions for compilation with torch.compile. This page follows the compiled JAX and eager PyTorch paths, then shows the corresponding APIs in each framework.

From Python to an accelerator

Both frameworks pass through dispatch, compiler, runtime, and hardware layers. Their default execution paths arrange those layers differently.

Eager PyTorch dispatches tensor operations as Python calls them. A call such as torch.matmul selects an implementation for the tensor's device and dtype, then queues work on the accelerator. Python can continue while queued GPU work runs asynchronously.

jax.jit traces before it executes. On a cache miss, JAX calls the function with abstract values that carry information such as shape and dtype. It lowers the resulting jaxpr through StableHLO, and XLA compiles an executable for the target device.

Hover or focus a layer to inspect it. JAX also targets NVIDIA GPUs through XLA, and PyTorch reaches TPUs through PyTorch/XLA.

How jit traces a function

jax.jit does not read your source code. It calls your function with tracers, objects that know their shape and dtype but hold no values, and records every JAX operation they flow through. The record is a jaxpr: a tiny functional language with one equation per primitive.

Three consequences follow, and they explain most first-week surprises:

  • Ordinary Python executes while JAX traces. A print inside a jitted function runs on a cache miss and prints a tracer. A later cache hit runs the compiled executable without executing that Python statement again.
  • A Python if needs a concrete condition. if x.sum() > 0: asks Python to convert a traced value to bool, so tracing fails. Use a JAX control-flow operator such as lax.cond when the condition is computed at run time.
  • Compilation is specialized. JAX caches compiled executables for compatible abstract argument signatures, including shape and dtype. Changes to shapes or static arguments can cause another trace and compile.

Eager PyTorch executes the Python function on every call, so data-dependent Python control flow works, though converting a CUDA tensor to a Python boolean synchronizes with the GPU. With torch.compile, TorchDynamo captures graph regions and checks guards before reusing them. Unsupported code can cause a graph break: PyTorch compiles the region captured so far, runs the unsupported part in Python, and then resumes capture.

Fusion reduces memory traffic

An H100 SXM has about 989 TFLOP/s of dense bf16 tensor-core throughput and about 3.35 TB/s of HBM bandwidth. Operations with little arithmetic per byte, including many elementwise operations, are usually limited by memory traffic rather than arithmetic throughput.

In the simplified pointwise chain below, eager PyTorch launches one kernel per operation and materializes each intermediate tensor in HBM. XLA and the default Inductor backend of torch.compile can fuse compatible operations into one kernel, keeping intermediates in registers or on-chip memory. Actual fusion depends on shapes, operations, backend, and compiler decisions. Reductions and library calls such as matrix multiplication often form boundaries, although compilers can fuse some pointwise work into them.

Automatic differentiation

Both frameworks support reverse-mode automatic differentiation. Their common high-level APIs expose the result differently.

PyTorch records a dynamic autograd graph during the forward pass. loss.backward() traverses that graph and accumulates gradients into leaf tensors such as parameters. The graph reflects the operations that actually ran.

jax.grad(f) returns another function. JAX linearizes the traced computation and transposes the linear part to implement reverse mode. Calling the transformed function returns gradients as values, so it can be composed with jit, vmap, and further differentiation.

Function transformations

jit, grad, and vmap each take a function and return a function. They can be nested, and the order determines the program JAX builds.

vmap applies batching rules to primitives. Code written for one example can therefore accept a batch without a Python loop. In the example below, a vector dot product becomes a batched dot_general. Per-example gradients can be written as vmap(grad(loss)).

PyTorch provides corresponding function transforms in torch.func, including torch.func.grad and torch.func.vmap. torch.compile can then compile compatible regions of the resulting function.

State and randomness

JAX transformations give a function functional semantics: parameters, optimizer state, and random keys are explicit values, while array updates return new arrays. XLA may reuse a buffer when its analysis proves that doing so preserves those semantics.

Common PyTorch training code stores parameters in an nn.Module and updates them through an optimizer. PyTorch also maintains default random generators per device, and APIs may accept an explicit generator. The usual stateful style is concise, while the function signature alone does not list every value the step reads or changes.

The widget compares those common styles. Its random values are illustrative. JAX sampling is a deterministic function of a key, and splitting derives distinct keys; exact cross-device behavior can depend on the selected PRNG implementation.

TPU and GPU matrix multiplication

A TPU TensorCore contains matrix-multiply units (MXUs), vector units, and scalar units. The MXU uses a systolic array: values move through a regular grid of multiply-accumulate cells according to a schedule chosen by the compiler. MXUs are 128 × 128 before TPU v6e and 256 × 256 in v6e and TPU7x.

An NVIDIA GPU is a general-purpose parallel machine. Work is split into thousands of threads grouped in warps of 32 and scheduled across dozens of streaming multiprocessors, each with tensor cores for matmul and a hierarchy of caches and shared memory. Irregular workloads, dynamic shapes and hand-written kernels all fit, because the hardware finds parallelism at run time.

The diagrams compare two simplified scheduling models. The TPU example shows data movement through a small weight-stationary systolic array. The GPU example shows thread blocks assigned to streaming multiprocessors at run time. Real matrix multiplications tile work across many hardware units and use several levels of on-chip memory.

Sharding across devices

JAX can map logical array dimensions onto a named device mesh. The compiler propagates those shardings through the computation and inserts collectives such as all-gather, all-reduce, and reduce-scatter when values must move between devices.

PyTorch offers several levels of control. DistributedDataParallel replicates the model and synchronizes gradients. FullyShardedDataParallel shards parameters and gathers them as needed. DTensor represents tensor placements over a device mesh and supports annotation-based parallelism.

Reach for JAX when

  • You are training or serving on TPUs, or scaling one program across hundreds of chips where compiler-managed sharding pays off.
  • Your workload has stable shapes and benefits from compiler optimization across large function regions.
  • You need higher-order derivatives, per-example gradients or other function transformations as first-class tools.

Reach for PyTorch when

  • You want eager execution as the default while iterating on dynamic models or data-dependent control flow.
  • Your dependencies and deployment tools are built around the PyTorch ecosystem.
  • Your team prefers stateful modules and wants to add compilation selectively.
