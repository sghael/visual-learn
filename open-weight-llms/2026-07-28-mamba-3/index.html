Mamba-3 · MIMO 1.5B

How a recurrent state can remember more through richer updates

Keeping a fixed-size state avoids an ever-growing attention cache, but it creates another challenge: what can that state represent? Mamba-3 changes how information enters, moves within, and leaves the state. Its contribution is richer recurrent computation rather than merely repeating Mamba’s original memory argument.

Separate the research date from the weight release

The Mamba-3 paper appeared March 16, 2026. This folder uses July 28, the dated “Mamba-3 public release” commit in the official 1.5B MIMO weight repository. The public API confirms the repository is neither private nor gated; an obsolete authentication sentence remains in its README. [1] [2]

The model card describes a pretrained, attention-free language model with 24 layers, MIMO rank four and Apache 2.0 licensing. It is a research checkpoint, not an instruction-tuned chat assistant. The card lists its own training data and context configuration, so experimental paper results should not automatically be assigned to this download. [3]

The mechanism starts with a recurrence: use the old state and the incoming token to calculate the next state. A fixed-size array can evolve indefinitely, but every update must decide what information survives.

Mix information from both ends of an interval

Mamba-3’s exponential-trapezoidal update adds contributions from the previous and current projected inputs while exponentially transforming the old state. In simplified notation: new state = a × old state + b × previous input + c × current input. The learned coefficients and projections are more structured than this scalar shorthand. [1]

For an independent numerical example, take old state 10, previous input 2, current input 6, decay 0.8 and an equal-endpoint mixture with unit step. The contributions are 8, 0.8 and 3, totaling 11.8. Using only the current input with unit weight would instead give 14. The point is the additional way to combine neighboring inputs, not that either number is universally better.

The name comes from approximating continuous state-space dynamics at discrete token steps. It does not mean text arrives as a physical fluid. Continuous mathematics supplies a principled family of update rules that can then be trained on sequences.

Remember direction as well as magnitude

A decay-only scalar transition shrinks stored values without rotating them. Mamba-3 introduces complex-valued dynamics implemented through pairs of real coordinates and input-dependent rotations. The paper connects this formulation to a data-dependent rotary transformation, rather than ordinary fixed-position RoPE. [1]

Picture a two-coordinate state [1, 0]. A ninety-degree rotation changes it to [0, 1]; another gives [−1, 0]; another gives [0, −1]. Its length stays one while its direction tracks four different stages. Multiplying by a positive decay alone cannot perform that cycle.

This tiny cycle is an invented geometric example, not a claim that a trained channel literally stores a four-state counter. It shows why allowing rotation expands the kinds of transitions available. Learned input-dependent angles can make an event affect the stored orientation differently from another event.

Do more computation while the state is already available

MIMO means multiple-input, multiple-output. The authors’ technical post explains the hardware motivation: a recurrent decode step can spend much of its time moving state rather than doing arithmetic. More useful arithmetic may fit into that same memory-bound interval. This is a measured design opportunity, not a universal free-compute rule. [4]

As an illustration, suppose reading and writing a state costs ten time units while the existing arithmetic costs two and overlaps with that traffic. Increasing arithmetic to four might leave total time close to ten. Increasing it to twenty would not. The outcome depends on implementation, overlap and hardware.

MIMO supplies multiple projected input/output directions for the state update. Think of taking several views of the same stored array while it is available. It does not mean generating several independent text tokens at once, and it does not require multiplying the state size by the MIMO rank. [4]

A better state still has finite capacity

The figure isolates a hypothetical 256-scalar recurrent state and a cache adding 64 scalars per token. Doubling the sequence length doubles the cache but leaves the state’s size fixed. Actual Mamba-3 also needs weights, projections, temporary buffers and a constant amount of update information; this is not its measured memory footprint.

The authors report that retrieval remains an important challenge for pure recurrent models and investigate hybrids with attention. Richer updates improve what a bounded state can encode; they do not make it a lossless archive of arbitrary history. [4]

Mamba-3 therefore addresses three questions within one constraint: how to combine adjacent input information, how to represent richer transitions, and how to use hardware while updating a state. The flat memory line motivates the work; the new update rules are the contribution.

What this tutorial leaves out

  • Folder date is the official weight-repository public-release commit, not the March paper date.
  • The download is a base research checkpoint; paper benchmark results are not automatically results for this artifact.
  • Toy arithmetic and state sizes do not reproduce the trained model or prove unlimited retrieval.
  • More arithmetic at similar decode latency is workload-dependent.
