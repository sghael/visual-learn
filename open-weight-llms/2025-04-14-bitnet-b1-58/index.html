BitNet b1.58 2B4T

How a network learns to compute with minus one, zero, and plus one

Weights are usually represented with many possible numerical values. BitNet restricts the weights used in its linear layers to three values, with a scale that restores magnitude. The model learns under that restriction instead of having the restriction imposed only after training.

Three choices are enough to define a different arithmetic

A ternary weight has three states: minus one, zero, and plus one. Multiplying an activation by those states means negating it, ignoring it, or retaining it, before accounting for scale. A matrix-vector product can therefore be implemented with specialized addition and lookup operations.

The 2B4T release replaces ordinary linear layers with BitLinear layers, quantizes weights using an absolute-mean scale, and uses eight-bit activation quantization. It was trained from scratch under this regime. [1] The name “1.58” comes from log₂(3), the information needed to distinguish three equally likely states in an ideal coding argument. It is not a promise that every parameter in every serialized file occupies exactly 1.58 bits.

For a toy scale of 0.5, a latent weight of 0.65 is mapped to the code +1 and reconstructed as 0.5. Move the latent value below the boundary and the forward value jumps. The mapping has flat intervals, which becomes important when trying to learn.

Learning needs a path through rounding

Ordinary differentiation of rounding gives zero almost everywhere and is undefined at the jumps. If an optimizer followed only that derivative, tiny changes to a latent weight would appear unable to improve the loss. Quantization-aware training therefore uses a surrogate gradient, often described as a straight-through estimator.

The conceptual loop is: keep higher-precision latent values for optimization; quantize for the forward computation; measure the loss; use a chosen backward approximation to update the latent values. This is a training method with approximation error, not a theorem that rounding is differentiable. The earlier BitNet b1.58 work describes the native low-bit design that the later release scales up. [2]

Suppose a latent weight moves from 0.20 to 0.24. At a scale of 0.5 it may stay on the same forward code. A later change to 0.30 crosses the threshold. Several latent updates can therefore accumulate before a visible forward change occurs. That is why the hidden optimization state and deployed representation should not be confused.

A model and an implementation must agree

The official model card identifies the two-billion-scale checkpoint, its training-token count, context configuration, and intended implementation. [3] The release is not an instruction to round any existing large model to ternary values and expect the same behavior.

A general-purpose inference engine might unpack ternary codes into floating-point values and run ordinary matrix multiplication. That can preserve the represented calculation while losing much of the intended efficiency. A specialized implementation can exploit the restricted arithmetic and packing. The official BitNet repository provides CPU-oriented inference tooling and records the April 14, 2025 model release. [4]

For intuition, imagine storing directions as “left,” “stay,” and “right.” A compact representation saves storage only if the program understands the code. If the program expands every direction into a long record before every operation, some of the advantage disappears. The entire execution path matters.

Precision savings do not measure language quality

Compare two different claims. “Three states require fewer stored codes than a sixteen-bit number” is an arithmetic statement. “This trained model answers a particular question correctly” is an empirical statement. The first cannot prove the second.

The release reports evaluations against models of similar scale, and its training uses pretraining, supervised fine-tuning, and DPO. [1] Those evaluations depend on the tasks, prompts, data, and implementations. They do not establish a universal advantage for low-bit training at every model size or every task.

Weight memory is only one component of inference memory. Embeddings, scales, KV caches, activations, and runtime workspaces still matter. Training also maintains state beyond the low-bit forward weights. A careful experiment records the actual process memory and task quality, alongside the nominal bit width.

What this tutorial leaves out

  • The displayed scale is fixed for teaching; actual quantization uses tensor statistics.
  • Theoretical code entropy, physical storage format, and total runtime memory are different quantities.
  • No hardware speedup or accuracy estimate is computed by this page.
