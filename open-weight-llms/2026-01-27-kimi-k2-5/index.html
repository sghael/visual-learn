Kimi K2.5

How seeing and delegating change an agent’s work

Some problems need better evidence; others need several independent pieces of work at once. Kimi K2.5 addresses both: images and video enter the model, while a trained orchestrator learns to divide suitable tasks among parallel agents.

4 sections · about 8 minutes · Multimodal

Release: 2026-01-27. Public weights January 27, 2026; arXiv report February 2, 2026.Model: About 1T total · 32B activeWeight license: Modified MIT license; attribution condition for large-scale products

Visual evidence must affect the decision

K2.5 builds on K2 with a vision encoder, a projection into the language representation, and joint visual-text training. The report describes MoonViT-3D, which shares an embedding space for images and video, plus temporal pooling: after joint processing, corresponding patch representations from groups of up to four consecutive frames are averaged before projection into the language model. This reduces the number of video tokens, while sacrificing some temporal detail in the compressed representation. The text backbone remains a sparse K2-family model.

[1]

Imagine debugging a webpage from its screenshot. Source code may say that two labels are centered, yet the rendered picture can reveal overlap. A model seeing that picture can formulate a different repair than one reading source alone. Its usefulness depends on whether it identifies the actual mismatch, rather than describing generic design advice.

The report’s “zero-vision SFT” has a narrow meaning: a text-only supervised fine-tuning stage activates tool behavior after multimodal pretraining. It does not mean the model learned vision without images. Outcome-based visual reinforcement learning then trains tasks whose answers require visual evidence.

[1]

Independent work can overlap in time

Suppose four independent lookups take 3, 2, 4 and 1 time units. One worker needs 10 units. With several workers, tasks can overlap, but completion still waits for the longest occupied worker. Our scheduler assigns each new task to the worker that becomes available first. Change the worker count to see the resulting schedule.

This calculation says nothing about model intelligence. It assumes known task durations, independent work, no failed calls and zero coordination overhead. Real agents must first discover a useful decomposition. If task B needs task A’s result, they cannot be made independent merely by assigning them different agents.

The useful quantity is the critical path: the dependent chain that determines when the final result can exist. Spawning more agents helps only if it shortens that path enough to pay for the coordination it creates.

Reward useful delegation, not agent count

K2.5’s Parallel-Agent Reinforcement Learning trains an orchestrator while its subordinate agents are frozen. Early auxiliary rewards encourage delegation and successful subtask completion; their weights are gradually reduced to zero so that final task performance drives the objective. The authors use a critical-step metric: add the main agent’s steps to the longest subagent branch in each stage, then sum across stages. One main-agent step followed by parallel branches of 3, 2 and 4 steps therefore costs 5 critical steps, although the agents performed 10 steps in total. This counts model/tool steps, not measured seconds.

[2]

This addresses two different bad strategies. An orchestrator may always do everything itself because it never explores delegation. Or it may create many agents merely because agent creation is rewarded. A useful reward must distinguish actual progress from visible activity.

For our lookup example, asking three agents to retrieve the same document does not automatically create three independent facts. Asking one to retrieve a number, one to check its definition and one to verify the period may be helpful, but only if the final answer reconciles their evidence. Parallel execution makes disagreement more likely to appear simultaneously; integration remains work.

Separate the research system from the released checkpoint

The official launch describes Agent Swarm as a research-preview product mode. The open model card supplies the K2.5 checkpoint and inference instructions. A downloadable checkpoint does not by itself reproduce the orchestrator training environment, the tool fleet or the hosted swarm product.

[2] [3]

When reading a reported agent score, check the tools, thinking mode, context handling and number of attempts. The release’s evaluation notes vary these by task; some coding results use non-thinking mode. A single model can therefore appear in several materially different systems.

[2]

The two innovations on this page connect through evidence. Vision changes what an agent can observe. Parallel orchestration changes how quickly independent observations can be gathered. Neither removes the need to check whether the resulting answer actually follows from those observations.

What this tutorial leaves out

  • Agent Swarm system results are not presented as capabilities reproduced by downloading weights alone.
  • The scheduler computes toy task duration; it does not call models or simulate reasoning.
