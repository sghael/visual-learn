# Kimi K2.5

How seeing and delegating change an agent’s work

Open `index.html` directly in a browser, or follow this folder from the collection index. All runtime CSS and JavaScript are local; there is no build step. Google Fonts are optional and have system fallbacks.

## What the tutorial teaches

Kimi K2.5 adds native visual input and studies learned parallel task orchestration.

- Visual evidence must affect the decision
- Independent work can overlap in time
- Reward useful delegation, not agent count
- Separate the research system from the released checkpoint

## Figures

- **Visual action produces new evidence** (`flow`): Illustrative visual debugging loop; not a measured K2.5 trajectory. Seeing the result closes a feedback loop that source text alone cannot supply.
- **Work and elapsed time are different quantities** (`parallel`): Illustrative independent tasks with arbitrary time units, greedy scheduling and no coordination overhead. Not measured Kimi throughput. Parallel work reduces latency only when the dependency structure permits it.
