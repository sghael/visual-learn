How a training corpus becomes a design choice

A larger neural network is only one way to spend a training budget. Another is to show a smaller network more useful examples. Qwen2.5 makes the second choice visible: its central lesson is the design of the training curriculum, rather than a new attention mechanism.

A pile of text is not yet a curriculum

A language model repeatedly predicts the next token, a piece of text such as a word fragment or punctuation. Its training distribution determines which predictions it practices. Ten thousand nearly identical product descriptions provide different experience from ten thousand distinct worked problems, even when the token counts match.

Qwen2.5 expanded its pretraining corpus to as many as 18 trillion tokens. The report describes quality scoring with earlier Qwen models, incorporation of mathematics and code data, filtered synthetic examples, and deliberate adjustment of the domain mixture. These are changes to the evidence presented during learning, not proof that any individual synthetic answer is correct.

[1]

Consider an illustrative box of 100 exercises: 80 repetitive advertisements, 15 stories, and 5 mathematical explanations. Doubling the box preserves the imbalance. Replacing 30 advertisements with checked technical exercises changes the training question itself. The useful comparison is both how much material the learner sees and what proportion teaches each skill.

Training cost and serving cost pull in different directions

Use N for parameter count and D for the number of training tokens. A common rough estimate for dense-transformer training work is 6ND floating-point operations. This approximates the main weight-matrix operations and omits sequence-length-dependent attention work and other overhead. The useful relationship is multiplicative. At a fixed budget, halving N allows roughly twice D. This arithmetic describes a budget, not the accuracy a particular model will achieve.

In the widget, begin with an illustrative 7-billion-parameter model trained on one trillion tokens. Moving to 14 billion parameters leaves room for half as many training tokens under the same approximation. Moving to 3.5 billion permits twice as many. Yet the smaller network must express what it learns using fewer weights. There is no conservation law that preserves intelligence when N and D trade places.

The deployment implication runs in another direction: every generated token of a dense model uses broadly the same network. Paying for longer training once can therefore be attractive when the resulting weights will answer many requests. Qwen2.5 provides multiple dense sizes for different resource budgets; its initial release did not make every size equally licensed.

[2]

Conversation length creates a separate memory bill

The trained weights remain fixed during ordinary inference, but the conversation grows. Attention keeps a cache of keys and values from earlier tokens so that a new token can retrieve useful context. That cache is additional to the model weights.

Qwen2.5-7B uses 28 query heads and 4 key/value heads across 28 layers. A query head asks what context to retrieve; key and value heads supply the matching and retrieved representations. Sharing those key/value heads among several query heads is grouped-query attention, inherited from earlier work. Its model card distinguishes a 32,768-token default configuration from longer inputs supported with YaRN scaling; the maximum advertised length is not the default setting of every runtime.

[3]

Set the widget to 4,096 tokens. Using bf16, a 16-bit format with two bytes per stored number, its estimate is 2 × 28 × 4,096 × 4 × 128 × 2 bytes, about 224 MiB for one sequence. Double the context and the cache doubles. Switch to ordinary multi-head attention and the same toy calculation uses seven times as many key/value heads. This comparison holds the other dimensions constant; it does not measure application speed.

Read the release as a bundle of choices

The instruct checkpoint adds training for useful responses after pretraining. The release emphasizes structured output and instruction following, while specialized Coder and Math checkpoints have different emphases. A model that prints valid JSON and a model that solves a theorem are exercising different learned behaviors; a single leaderboard average hides that distinction.

[2]

The enduring lesson is experimental discipline. Compare base with base when studying pretraining. Compare instruct with instruct when testing user-facing behavior. Keep the prompt format, context setting and evaluation data fixed. A better result can arise from data selection, post-training or inference configuration even when the underlying transformer block is familiar.

What this tutorial leaves out

  • The training-budget widget approximates dense weight-matrix work; it omits attention’s dependence on sequence length and is not a scaling-law fit.
  • Qwen2.5-Turbo was an API model; its million-token configuration is not attributed to the September open checkpoints.
