gpt-oss-20b and gpt-oss-120b

How sparse weights, low precision, and a conversation protocol make reasoning deployable

A model must fit in memory before it can answer anything. It must then execute the right computation and communicate with tools in the format it learned. gpt-oss combines sparse expert layers, quantized expert weights, and explicit message boundaries. Those are three different engineering problems, and each requires its own explanation.

Stored weights and active weights are different

A mixture of experts replaces a single feed-forward network with a bank of networks and a router. The router selects only a few for each token. OpenAI’s release lists 128 experts with four selected in gpt-oss-120b, and 32 with four selected in gpt-oss-20b. The larger model has 36 layers; the smaller has 24. Both are text-only models. [1]

Imagine a workshop with 128 workbenches. A particular job visits four of them. Counting the visited benches estimates part of the work, but all 128 benches still occupy floor space. Likewise, inactive experts save arithmetic for that token without disappearing from memory. Attention and shared operations also contribute to the active parameter count, so four divided by 128 is not the active fraction of the entire model.

Store expert weights in fewer bits

The expert weights were released in MXFP4, a microscaled four-bit floating-point format. Groups of low-precision values share scaling information. Inference code must interpret that representation correctly; it is not interchangeable with an arbitrary four-bit integer format. OpenAI provides reference implementations and recommends checking implementations for agreement. [2]

The simplest memory estimate is a useful lower bound. Twenty-one billion weights at sixteen bits require 42 billion bytes. At four bits they require 10.5 billion bytes, if every weight used that format and there were no metadata. Neither assumption describes the complete gpt-oss runtime. Some weights remain at other precisions, and the KV cache, activations, scales, and working buffers require additional memory.

Move between bit widths below. The arithmetic changes exactly; accuracy does not appear on this plot because memory arithmetic cannot predict quantization error. OpenAI’s deployment guide discusses actual supported implementations and their larger memory requirements. [3]

A tool call needs a boundary

A text model can emit the words “I used a calculator” without any calculator running. A working tool system needs an unambiguous handoff: who speaks, which tool receives the request, when the model yields control, and how the result returns. The model generates a request; application code performs the action.

Harmony is the conversation format used by gpt-oss. It distinguishes roles, channels, recipients, and endings. Analysis and final-answer messages occupy different channels. A tool handoff is distinct from ending an ordinary message or finishing the assistant turn. [4] The value of these distinctions is operational: the host knows whether to call a function, resume generation, or return an answer.

For a toy arithmetic task, the host might receive a calculator request, run the calculation, append the result as a tool message, and resume the model. The host must still validate arguments and decide which tools are permitted. A structured request is a format guarantee only to the extent the surrounding system enforces it.

More reasoning changes the inference budget

The released models support low, medium, and high reasoning effort. Their post-training includes supervised learning and reinforcement learning for reasoning and tool use. The model card describes these capabilities and their limits. [5] A higher effort setting changes how the model is asked to work; it does not swap in a larger weight file.

Suppose two settings produce the same final sentence, but one generates many more intermediate tokens and makes two tool calls. They can have very different latency and cost. The relevant budget includes generated tokens, attention over the expanding context, external tool latency, and any retries. Total parameter count hides those differences.

Longer output is not a proof of better reasoning. An intermediate explanation may be mistaken, or fail to describe the computation that produced the answer. Judge the result on a task with a dependable check, compare the same task at each setting, and include unsuccessful attempts in the measurement.

What this tutorial leaves out

  • The two sizes share this tutorial because the mechanism is shared; their parameter and expert counts differ.
  • The four-bit chart is an ideal lower bound, not a claim that the whole model uses four bits or fits in a particular device.
  • This tutorial does not infer an undisclosed full training-data recipe from the released weights.
