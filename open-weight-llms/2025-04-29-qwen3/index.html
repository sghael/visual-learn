Qwen3

How one model learns when to deliberate

Answering a greeting and solving a difficult proof should not consume the same amount of computation. Qwen3 treats the amount of reasoning text as a controllable inference choice, then transfers that behavior from large models to smaller ones.

4 sections · about 8 minutes · Reasoning

Extra tokens are extra computation

A generated reasoning token becomes part of the context for later tokens. Writing intermediate steps therefore lets a model perform additional sequential computation before it commits to an answer. It may also make mistakes, repeat itself, or follow a bad premise. Length measures expenditure, not correctness.

The original Qwen3 release supports thinking and non-thinking modes within its post-trained checkpoints. The official announcement ties this to adjustable thinking budgets and releases both dense and mixture-of-experts models. In the 235B-A22B name, 235 billion describes total parameters and 22 billion describes the approximate active parameters per token.

[1]

For a concrete distinction, imagine multiplying 17 by 23. A direct reply can output 391 without showing intermediate text. An explicit route can split 23 into 20 + 3, calculate 340 + 51, and return 391. A short answer alone does not tell us which computations produced it. The extra sequence exposes intermediate arithmetic to subsequent computation. It does not make the final answer infallible.

Teach the behavior before transferring it

The Qwen3 report describes four stages for its flagship post-training: long-reasoning examples, reinforcement learning on verifiable problems, fusion of thinking and direct-answer behavior, and general reinforcement learning. Smaller models use strong-to-weak distillation rather than independently repeating the entire expensive process.

[2]

Separate the purposes. An example teaches what a successful trajectory looks like. A verifier judges whether a sampled attempt reaches a correct result. Mode fusion teaches that the same prompt may call for either a compact answer or extended deliberation. Preference training addresses behavior outside problems with an exact numerical answer.

Consider teaching a student to solve equations. Showing one worked solution establishes the format. Asking it to solve new equations and checking the answers provides feedback. Teaching when a one-line response is adequate is another lesson. These operations cooperate, but one cannot replace the others merely by increasing the number of examples.

A teacher can provide more than a winning token

A hard target says only “choose A.” A probability distribution can say “A is plausible, B is somewhat plausible, C and D are unlikely.” Distillation trains a student to match information in a teacher’s outputs. Qwen3 first trains smaller models on teacher-generated responses, then lets each student generate its own responses and matches the teacher’s next-token distribution along those student trajectories. The report uses teacher logits, the scores from which probabilities are computed. This second, on-policy stage teaches at contexts the student actually reaches, including its imperfect choices.

[2]

The toy below uses scores 4, 2, 1 and 0. Softmax turns score z into a probability proportional to exp(z/T), where T is temperature. Raising T spreads probability across alternatives. Lowering T concentrates it. The temperature slider changes this illustrative distribution; it does not reproduce the temperature or objective used by Qwen3.

Suppose the student assigns almost all probability to B. A hard A target names the correct token but supplies no teacher preference among B, C and D. A soft teacher can convey those relative preferences too. Conversely, a teacher that is confidently wrong can transmit a systematic error. Distillation is a method of transferring behavior, not an independent source of truth.

Mode control must survive the chat template

Qwen3-8B’s model card shows a hard template switch, enable_thinking, and the conversational /think and /no_think controls when thinking is enabled. The template determines which tokens frame the response. These controls describe the original release, not every later checkpoint carrying Qwen3 in its name.

[3]

This matters in an application. If a benchmark silently disables thinking while another allows a long trace, the two scores measure different compute budgets. The report’s thinking-budget procedure ends the reasoning segment and inserts an instruction to give the answer; it still reserves generation for that answer. Simply truncating the entire response at the same token count can instead stop before an answer arrives. [2]

A useful evaluation records final-answer correctness, tokens generated, elapsed time and whether the answer arrived at all. It should test both easy and difficult requests. The question is whether the additional computation improves the task enough to justify its cost, and whether the smaller distilled model preserves that tradeoff.

What this tutorial leaves out

  • Generated reasoning is not a faithful explanation of every internal computation.
  • The softmax widget teaches distillation information; it does not implement training or predict student quality.
