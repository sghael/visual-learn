Phi-3 · mini

How choosing the curriculum can matter as much as increasing the model

A small model cannot devote unlimited capacity to every fact on the web. Phi-3-mini asks what happens when its training material is chosen for the skills we want it to learn. The lesson is a relationship between capacity, curriculum and the cost of deployment.

Choose the student before choosing the curriculum

Microsoft publicly released Phi-3-mini on April 23, 2024, with weights available through Hugging Face and local deployment options. The initial released mini model has 3.8B parameters. The announcement’s broader family plans should not be mistaken for all models sharing that first weight-release date. [1]

Imagine teaching a compact model to solve small programming problems. A repository might contain useful algorithms, repeated boilerplate, generated files, documentation fragments and broken experiments. More text does not automatically mean more useful practice. Under a fixed training budget, every repeated file occupies time that another example could have used.

This is not a claim that a small model has a tidy compartment for each fact. Parameters participate in distributed representations. “Capacity” is a shorthand for the limitations imposed by its architecture, size and training, not a literal number of facts that fit into labeled drawers.

A worked example supplies intermediate structure

The earlier “Textbooks Are All You Need” work studies filtered code and synthetic textbook-style examples for smaller models. Its synthetic-data discussion warns that naive generation can produce homogeneous material, then describes constraints intended to diversify topics and exercises. Phi-3 extends this research direction; it did not invent the idea that training data quality matters. [2]

Compare two invented examples. One says only “the sum is 45.” The other lists the input values, shows a loop accumulating them, and tests the returned sum. The second exposes connections that the first leaves implicit. It gives next-token training more opportunities to learn a useful sequence of operations.

Diversity still matters. A thousand nearly identical addition examples do not cover subtraction, empty inputs, incorrect types or overflow. A synthetic curriculum should vary the underlying problem, not merely rename the variables. And a beautifully formatted wrong explanation remains wrong.

Phi-3 uses both filtering and synthesis

The Phi-3 report describes 3.3T training tokens for mini, combining heavily filtered web content with generated examples. It describes an earlier phase emphasizing broad language and knowledge, followed by a phase emphasizing more strongly filtered and synthetic material. The architecture remains a transformer with a Llama-like block structure. [3]

Filtering and synthesis have different roles. Filtering selects existing material. Synthesis creates or rewrites material into another form. In an illustrative curriculum, a web passage might supply the underlying concept, while a generated exercise turns it into a question with an explicit solution. Checking the solution prevents the generation stage from silently corrupting the lesson.

The report also acknowledges weaker factual recall in some settings. That is an important boundary: success on reasoning exercises does not establish equal coverage of arbitrary trivia. The choice of curriculum can improve targeted skills while leaving gaps elsewhere. [3]

A compact model changes what can be stored locally

The model card identifies Phi-3-mini as a 3.8B-parameter model and supplies an MIT license. Smaller weight arrays make local deployment more approachable, but deployment still depends on numerical precision, runtime support and working memory. The public model is an artifact that can be measured directly. [4]

The interactive calculation starts with 3.8 billion numbers. At sixteen bits each, ideal weight storage is 7.6 decimal GB. At eight bits it becomes 3.8 GB; at four bits, 1.9 GB. These are independently calculated lower-level storage examples, not measured memory usage for a running phone application.

Quantization rounds or otherwise encodes weights into a smaller numerical representation. Its error can change the model’s outputs. The slider therefore shows a resource tradeoff only. It has no evidence about how a particular quantizer preserves accuracy or how a particular phone schedules the computation.

Test the curriculum’s blind spots

Try separating an evaluation into two questions. Can the model execute a familiar kind of reasoning on a new example? Does it know the external facts required by the question? A failure of either kind may look like a wrong answer, but each calls for a different intervention.

For instance, a model might correctly calculate travel time from a supplied distance and speed while having no reliable knowledge of a newly opened train route. Supplying a trustworthy document could address missing information. It would not automatically repair an inability to combine the values correctly.

Phi-3’s lasting lesson is to treat data design as part of model design. The relevant result is a trained system under an explicit curriculum and evaluation, not a slogan that small models always replace large ones. A compact model can be useful when its learned skills and limitations match the task.

What this tutorial leaves out

  • The lesson focuses on mini, the first public Phi-3 release.
  • Educational-data selection does not prove a universal optimum or complete factual knowledge.
  • The memory calculator models ideal weights only.
