DeepSeek-V4

Compress the history before deciding where to look

A million-token context can contain a long sequence of documents and tool results. Keeping a detailed record for every token at every layer is expensive even when attention reads selectively. DeepSeek-V4 changes the stored history itself: groups of tokens become compressed entries, while a local path preserves recent detail. [1]

Compression can act across features or across time

Think of a notebook represented as a table: one row per token, one column per stored feature. Earlier latent attention compressed the columns, retaining fewer numbers for each row. V4 also compresses the rows, combining information from groups of token positions. These are distinct axes of the same storage problem.

An invented table with 1,024 rows and 256 columns contains 262,144 numbers. Reducing feature width to 64 leaves 65,536. Keeping the original width but combining every eight rows into one leaves 32,768. Applying both changes leaves 8,192 numbers. This arithmetic explains why independent compression axes can multiply.

The important caveat is information. Combining records may blur individual details. The model therefore needs learned compression and training that make the retained representation useful; storage savings alone do not establish good recall.

Compress groups, then select useful groups

Compressed Sparse Attention, or CSA, first creates fewer cached entries along the sequence dimension. A learned indexer then selects entries for attention. This combines compression with the content-dependent selection developed in DSA. A local sliding-window path supplies recent fine-grained information alongside the selected compressed history. [2]

Imagine 64 old passages compressed into sixteen records, then four of those records selected for close use. The widget starts at the selection step: each displayed candidate stands for a compressed record, not one original token. Changing the query can choose distant records. Changing the selected count changes how much compressed history is directly consulted.

The interpretation matters. Selecting four compressed records could expose information from more than four original positions, but it does not reconstruct all those positions exactly. Compression is a learned representation, not a lossless archive hidden behind a smaller label.

A coarse global view complements local detail

V4 interleaves CSA with Heavily Compressed Attention, or HCA. HCA compresses sequence entries more aggressively and attends densely to that smaller set. “Dense” here refers to access among compressed entries, not full attention over every original token. Both patterns retain a local attention component. [2]

A map analogy helps separate their jobs. A coarse map shows the whole region cheaply. A more detailed index lets a query focus on a few relevant areas. A local street view keeps immediate surroundings precise. None alone supplies every detail at every distance.

For an invented equal-width example, 4,096 original records compressed 16-to-1 become 256 records. Reading all 256 is dense over that coarse representation while still far smaller than reading all original records. This is a counting example, not V4’s actual compression setting.

More information paths need stable mixing

V4 also adopts manifold-constrained hyper-connections, or mHC. Ordinary residual connections carry a representation forward while adding a layer’s update. Hyper-connections widen this into multiple streams; mHC constrains how the residual streams mix to prevent uncontrolled amplification through repeated transformations. [3]

A small numeric example exposes the issue. Repeatedly multiplying a scalar by two gives 1, 2, 4, 8. Repeated mixing through a matrix with nonnegative entries whose rows and columns each sum to one behaves differently. For [[0.8, 0.2], [0.2, 0.8]], inputs [2, 6] become [2.8, 5.2]: each is a weighted blend of previous values.

The real method constrains a residual mapping, not every operation in the network. The example explains the stability motive without claiming that an entire nonlinear language model can never amplify an activation.

What the release establishes

The April launch provided two public-weight scales: V4-Pro at 1.6T total and 49B active parameters, and V4-Flash at 284B total and 13B active. The official card makes their weights available under MIT. These counts remain much larger than what “small active fraction” might suggest for storage. [1] [4]

The family also retains MoE and multi-token prediction while adopting Muon optimization. Those are additional training and architectural choices; this lesson’s memory arithmetic does not attribute all quality improvements to attention compression. [4]

A long supported context is a capacity specification, not a guarantee that every buried fact will be retrieved. To evaluate a long task, ask which details must survive compression, how much new input arrives per turn, and whether the serving system can reuse previous state. Those questions lead directly to V4.1’s attention to cache reuse across layers.
