DeepSeek-V2

Remember a compact description instead of every expanded view

DeepSeek-V2 attacks two different costs: storing the past and processing the present. Its public checkpoint has 236B total parameters with 21B active per token. The central memory idea is multi-head latent attention, or MLA: retain a compact learned description of each token and use it to supply attention. [1]

Several large views can share a small description

Suppose a toy system stores four readings: x, 2x, 3x and 4x. Saving all four is unnecessary when one number x and a known rule reproduce them. Real neural representations are not this tidy. But if their useful variation can be learned in a lower-dimensional space, storing the smaller coordinates can save memory.

That is the intuition behind a latent representation: coordinates in a learned internal space. A projection maps a token’s hidden state down to this smaller vector. Learned maps can then produce the key and value information used by the attention heads. MLA trains these maps as part of the model. [2]

The important difference from reducing precision is the axis being changed. Quantization uses fewer bits per number. Latent compression uses fewer numbers. Either can lose useful information unless the representation and training support it.

Make the storage bottleneck visible

The widget starts with an invented 512-number expanded representation and a 64-number latent. At two bytes per number, those are 1,024 and 128 bytes per token per layer before any positional side channel. For 1,000 tokens, multiply both quantities by 1,000. For 20 layers, multiply again by 20. The proportional difference survives those multipliers.

Increase the latent width. The smaller bar approaches the expanded bar because fewer dimensions have been removed. This is a storage accounting experiment, not a model-quality simulator: no curve here predicts how much accuracy a narrower latent would lose.

DeepSeek-V2’s actual MLA contains more structure than this picture. In particular, positional information has its own treatment. The diagram therefore teaches one compression axis instead of pretending to reproduce the checkpoint’s precise cache layout.

Position is information that compression must preserve

The model must distinguish “A precedes B” from “B precedes A.” Rotary position embeddings, commonly called RoPE, encode relative-position information by rotating parts of query and key vectors. Applying such position-dependent operations carelessly interferes with MLA’s efficient algebra. DeepSeek-V2 separates a rotary-position component from its compressed content component. [2]

Here is the algebraic reason a compact representation can be useful without expanding every key. If k = Uc, then a query score qᵀk equals qᵀUc, which also equals (Uᵀq)ᵀc. One can transform the new query and compare it with cached c. The large reconstructed k need not be written out for every past token.

The equality follows from associating matrix multiplications, not from approximating the result. The approximation lives in the learned low-dimensional representation. Position-dependent rotations complicate which operations can be combined, which is why the positional side channel is part of the design rather than a cosmetic detail.

Share routine work and route the remainder

DeepSeekMoE contributes a complementary idea: divide routed expertise into finer pieces and keep shared experts active for all tokens. The earlier DeepSeekMoE paper motivates shared experts as a place for common knowledge, so routed experts need not duplicate all of it. This architecture predates the V2 release. [3]

Imagine an invented workshop where every job needs one common preparation step, but then needs two of eight optional operations. The shared step always runs; the router chooses the optional pair. That does not prove the learned shared network contains only common knowledge. It states the computational organization.

Change the routed active count below. The always-active component remains. Consequently, “two of eight” is not the fraction of the entire model being computed: it ignores shared work and attention. V2’s real expert counts are larger than this teaching diagram.

Cache efficiency and weight size remain separate

V2’s repository reports a 128K context capability and an 8.1-trillion-token pretraining corpus. Those specifications describe the released model; they do not imply that every request will use the whole context effectively. Nor does a compressed cache remove the need to store the model’s large expert inventory. [1]

For a concrete deployment thought experiment, hold weights fixed and double the number of simultaneous conversations. Weight storage may stay shared, while the total cache demand roughly doubles if their lengths and representations match. Conversely, holding conversations fixed while adding more inactive experts primarily expands the model inventory. Different workloads expose different bottlenecks.

MLA and MoE therefore make a useful pair: one addresses memory left by previous tokens, the other limits feed-forward computation for a current token. DeepSeek-V3 inherits both and concentrates on making their large-scale training and execution work together.

What this tutorial leaves out

  • The latent-width slider does not model quality, RoPE storage or exact MLA implementation.
  • The expert widget uses scaled-down counts and cannot predict throughput.
  • The weights use the release’s custom DeepSeek Model License; code and weights have different licenses.
