How an open chat model learned to answer, and to remember more cheaply

A language model can continue a sentence without being a useful assistant. A useful assistant also needs a way to follow requests, improve from judgments, and retain a growing conversation. Llama 2 makes these separate engineering problems visible.

Prediction is a starting point

Llama 2 arrived on July 18, 2023, slightly before the three-year core of this collection. Meta released both base and chat checkpoints. That paired release matters: it lets us separate the ability to predict text from the behavior of responding to a person. The weights came with a custom community license rather than an unrestricted license. [1]

Imagine training on the fragment “The train leaves at”. The next word might be a time, a place, or an explanation. A token is a piece of text from the model’s vocabulary. During pretraining, the model assigns probabilities to possible next tokens and adjusts its numerical weights when the observed continuation was unlikely. This example describes a prediction exercise, not a dialogue contract.

A model trained this way could continue a question with another question from an exam sheet. It has learned a distribution over writing. Asking it to act as an assistant introduces a more specific target: produce a useful response to the preceding user request.

Demonstrations teach a response format

The Llama 2 report describes supervised fine-tuning followed by repeated rounds of human-feedback training. Demonstrations provide examples of desired responses. Human comparisons train separate helpfulness and safety reward models. Rejection sampling selects high-scoring candidate answers; proximal policy optimization also adjusts the model using reward. Llama 2 adopted these established methods and documented their combination. [2]

For an illustrative arithmetic prompt, one candidate could answer correctly with a clear calculation, another could be correct but confusing, and a third could be fluent and wrong. A preference comparison supplies information that the raw next-token target does not contain. It says which answer is preferred under the annotation rules.

This also explains a limitation. A learned judge is an approximation to those judgments. Improving its score does not prove every answer true. Keep factual verification and helpful presentation conceptually separate when reading a chat-model result.

Every new token consults the past

The second problem appears after training. Attention lets a current token query representations of earlier tokens. A key is used to match that query; a value carries information to combine into the result. Keeping keys and values avoids recalculating the entire past at every generation step.

Ordinary multi-head attention gives each query head its own key and value heads. Grouped-query attention, introduced by Ainslie and colleagues, lets several query heads share a key/value pair. The queries remain different; the stored memory has fewer parallel representations. Multi-query attention is the extreme with one shared pair. [3]

The released Llama 2 70B uses grouped-query attention. The 7B and 13B versions do not. The report also discusses a 34B model that was not part of the original public release; it should not be counted as a downloadable release here. [2]

Count the memory yourself

In the figure, each stored scalar takes two bytes. At 4,096 tokens, eight KV heads require 2 × 32 × 4,096 × 8 × 128 × 2 bytes, or about 0.54 decimal GB. The first factor of two is for keys and values. Giving all 32 query heads separate memories multiplies this result by four.

Double the conversation length with the slider. Both variants double their cache. Change to the single-pair setting: the slope falls again, but this chart cannot tell us what quality was lost. A memory calculation has no knowledge of the training data or the tasks the model must solve.

The model card lists a 4,096-token training context and distinguishes pretrained from dialogue-tuned checkpoints. That context allowance is separate from parameter count. Parameters are stored knowledge; the KV cache is working memory for this particular input. [4]

Two kinds of progress can reinforce each other

Consider serving many short conversations versus one long document. In the first case, weights and batching may dominate the engineering decision. In the second, the growing cache can become a major constraint. Grouping addresses only one term in that budget; it is not a promised fourfold speedup.

Llama 2 is useful as a foundation lesson because it separates three questions: what the model learns from text, how its behavior is shaped for conversation, and what the runtime must remember. Later releases change these pieces independently. A better chat answer is not evidence of a new attention mechanism, and a smaller cache is not evidence of stronger reasoning.
