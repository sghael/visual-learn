Phi-4-reasoning-vision-15B

How better visual evidence and selective reasoning solve different problems

An elaborate solution cannot recover a number that was never read correctly from an image. Phi-4-reasoning-vision separates accurate perception from the decision to spend more tokens reasoning. Both affect whether a compact visual assistant produces a useful answer quickly.

5 sections · about 8 minutes · Multimodal

Release: 2026-03-04. Model card and official research post both identify March 4, 2026 as the public-weight release.Model: 15B · image/text input · text outputWeight license: MIT

Read the marks before solving the problem

Microsoft released Phi-4-reasoning-vision-15B on March 4, 2026. Its model card specifies text-and-image inputs, text outputs, a 16,384-token context and an MIT license. It combines the Phi-4-reasoning language backbone with a SigLIP-2 vision encoder. [1]

Consider a chart asking which month had the highest revenue. The model first needs to identify the bars, labels and scale. If “18” is misread as “13”, a flawless later comparison can still choose the wrong month. Perception errors and reasoning errors can produce the same incorrect final answer, so evaluate them separately.

Now change the question to ask for the growth rate between two months. The visual evidence may be identical, but the required computation changes. A model should not need the same long response for simply naming a label and for deriving a percentage from two values.

More visual tokens preserve opportunities to inspect detail

SigLIP 2’s NaFlex variant supports varying image aspect ratios and resolutions. Its paper studies representations for localization and document-like tasks as well as broad image understanding. The representation is learned, rather than a fixed textual caption of the scene. [2]

The Phi report compares image-processing approaches using a smaller 5B experimental model. It favors dynamic-resolution encoding with a larger visual-token budget for fine-detail tasks. Those ablations motivate its design, but do not mean increasing resolution always improves every task or every model. [3]

The grid is an abstract image sixteen units wide and twelve high. With two-unit square patches, it contains 8 × 6 = 48 patches. With one-unit patches it contains 192. A full noncausal attention layer comparing every patch with every patch has 2,304 versus 36,864 ordered pairs. The number of pairs grows sixteenfold when the token count grows fourfold.

A projector connects vision to the language backbone

The report calls its design mid-fusion: the image encoder produces visual vectors, a learned multilayer projector maps them into the language embedding space, and those soft visual tokens are interleaved with text for the reasoning backbone. This reuses a trained language model rather than training every component from scratch. [3]

Imagine a visual vector and a language token vector as two lists of measurements using different coordinate systems. The projector learns a transformation that lets the backbone work with them together. It does not translate an image into a guaranteed complete sentence description; its outputs remain continuous numerical vectors.

Fusion terminology varies among papers. The important operation here is concrete: an encoder first processes the image, then a projector supplies representations to the language model. Follow that data path rather than assuming that every paper using the same fusion label has an identical architecture.

Train the model to spend effort selectively

Microsoft’s research post describes combining reasoning demonstrations with direct-answer data. The technical report identifies explicit <think> and <nothink> markers and a training mixture in which reasoning examples form about 20%. Users can request a mode, but the learned default can still make the wrong choice. [4] [3]

For a toy receipt, “What is the printed total?” mainly requires locating and reading a field. “Does the printed total equal the items plus tax?” requires extracting multiple fields and checking their arithmetic. The desired answer length is a consequence of what work is useful, not a fixed property of the image.

The mode markers give supervision a visible structure. They indicate which response pattern an example should teach. They do not install a perfect controller that knows in advance whether more computation will solve a particular problem.

When the answer is wrong, locate the failed step

Try an evaluation with three versions of the same problem: the original image, a faithful transcription of its contents, and the relevant values explicitly isolated in text. If the model fails only on the image, perception or visual grounding is implicated. If it fails on all three, reasoning, task understanding or missing background knowledge may be involved. Differences in prompting make this a way to narrow hypotheses, not a proof of a single cause. This is a proposed diagnostic, not a result from the release.

Then compare direct and extended response modes on the same task set. Record accuracy, generated length and elapsed time. The research post emphasizes balancing useful reasoning against unnecessary generation; a longer response should earn its cost through better outcomes. [4]

The two budgets remain distinct. More visual tokens may preserve evidence; more output tokens may support a longer calculation. Neither automatically compensates for the other. This model is a useful milestone because it treats those choices as separate design and evaluation problems.

What this tutorial leaves out

  • The patch grid is an abstract image-encoder cost illustration, not a faithful Phi tokenizer or runtime simulator.
  • Patchification does not mean every patch is reduced to its average color.
  • Learned selection between direct and reasoning modes is imperfect.
  • Visible reasoning text is not a guaranteed explanation of the model’s internal computation.
