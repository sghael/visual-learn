DeepSeek-V3.2 / Exp

Use a cheap search before expensive attention

Compressing a token’s memory does not remove the need to search a long history. DeepSeek-V3.2 introduces a second question: which cached tokens deserve the expensive attention calculation? A small learned indexer scores the past, then the main attention reads a selected subset. This design debuted in V3.2-Exp. [1]

A smaller record can still leave a large search

Suppose an assistant has read a long investigation and must answer, “Which experiment used the copper coil?” The relevant sentence might be far from the end. A short sliding window can miss it. Full attention can inspect every prior position, but its cost grows with the history.

DeepSeek Sparse Attention, or DSA, uses a lightweight scoring operation called the lightning indexer before the main attention. It selects high-scoring positions, then retrieves their cached entries. This is content-dependent selection: a token can matter because it matches the current query, not merely because it is nearby. [2]

The library analogy is an index that points to a few passages worth reading closely. However, the index is still searched, and a learned index can select poorly. The expensive part is made sparse; the whole process is not free.

Change the question, change the selected past

In this illustrative example, sixteen old tokens have scores for a current query. Selecting the largest four leaves twelve tokens out of the main attention calculation. Change the query preset: the score pattern and selected locations move. There is no requirement that those locations form a contiguous recent window.

Now increase k, the number of selected entries. More of the past becomes directly available to expensive attention. Decreasing k saves that part of the work but risks excluding useful information. No accuracy estimate is attached to this slider because the scores are invented and no language model is running.

The release’s sparse-training configuration selects up to 2,048 KV positions per query. The diagram scales that down to keep every choice visible. The underlying MLA representation is inherited; DSA changes which entries are read, rather than replacing expert routing with token routing. [2]

Teach the index before depending on it

V3.2 is obtained through continued training from a V3.1-Terminus base. First, dense attention remains active while the new indexer learns to approximate an attention-derived target. Then sparse selection is enabled and the model adapts to that restricted access. The indexer and main language-model objective receive separate optimization signals. [2]

Why use this order? Consider a new librarian whose index initially points to random pages. Removing access to the full book immediately would make both the index and the answerer unreliable. A warm-up gives the selection mechanism a useful starting rule before the rest of the system must depend on it.

In an invented 1,000-entry example, an indexer costing one unit per entry plus attention costing ten units per selected entry costs 1,000 + 10k units. At k = 100, that is 2,000 units versus 10,000 for expensive attention over all entries. These invented costs illustrate an inequality, not a measured release speedup.

Sparse access makes longer trajectories more practical

The December V3.2 model adds a substantial post-training effort around reasoning and tool use. The official model card describes synthetic agent tasks and environments used to train longer action sequences, while Speciale is a separate reasoning-focused variant. The card explicitly states that Speciale does not support tool calling. [3]

For an original example, an assistant might inspect files, run a test, read the failure, change a function and rerun the test. Each tool result adds input to the conversation. Better attention efficiency can reduce the cost of revisiting that growing history, while training must separately teach the assistant which action to take.

An architecture that reads cheaply does not automatically acquire useful tool habits. Conversely, a good task curriculum does not eliminate cache and attention costs. These contributions address different parts of a long interaction and should be evaluated separately.

Keep the two meanings of sparse apart

In MoE, sparsity selects parameter blocks: which feed-forward experts process this token? In DSA, sparsity selects history positions: which earlier token records inform this query? A model can use both, and the word “sparse” alone does not reveal which resource is saved.

Nor does selecting fewer history positions automatically shrink the whole KV cache by the same fraction. A later query can choose a different subset, so the system generally needs the wider candidate history available. DSA reduces access to the expensive attention stage; sequence compression in DeepSeek-V4 will also reduce the inventory of stored entries.

The official change log records September 29 for Exp and December 1 for the full release. Treating them as one day would hide the progression from the architecture experiment to the later reasoning-and-agent checkpoint. [4]

What this tutorial leaves out

  • The sparse widget uses invented scores and does not execute a model.
  • The lightning indexer still incurs work over candidate positions; attention sparsity does not make total computation independent of length.
  • Exp and full V3.2 share DSA architecture but differ in their release and post-training context.
