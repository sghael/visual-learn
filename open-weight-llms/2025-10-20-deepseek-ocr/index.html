DeepSeek-OCR

Can a page stand in for a long string of tokens?

A page of writing has two forms: a sequence of text tokens and an image containing letters arranged in space. DeepSeek-OCR explores whether the image can become a shorter sequence of learned representations while retaining readable text. The released weights make that optical-compression experiment inspectable. [1]

Count positions before counting savings

Imagine a page whose transcription occupies 1,000 text tokens. An alternative system renders the page, encodes the image into 100 vision tokens, then supplies those vectors to a decoder. The input sequence would have ten times fewer positions. These numbers are an invented example, not a DeepSeek benchmark.

A vision token is a learned vector summarizing an image region or features. It is not one word, one character, or one byte. A single vector can carry evidence about several characters, but decoding it may make mistakes. The ratio 1,000/100 describes sequence length; it says nothing by itself about information loss, vector precision, or encoding cost.

The distinction matters because attention operates over positions. A shorter representation can reduce downstream work, while building that representation adds its own work. Reconstructing all 1,000 output tokens still requires generating those tokens.

Compress before the expensive global stage

DeepEncoder combines a SAM-based visual stage using window attention, a convolutional compression bridge, and a CLIP-based stage using global attention. The approximately 380M-parameter encoder feeds a 3B mixture-of-experts decoder with about 570M active parameters. The components are inherited; their arrangement is the contribution to study. [2]

For a 1,024 × 1,024 image, 16-pixel patches initially yield 4,096 positions. The bridge reduces this count sixteenfold to 256 before global processing. Local perception therefore examines a richer grid than the later globally connected stage receives. [2]

Picture reading a newspaper. First inspect nearby marks carefully enough to distinguish letters; then assemble those observations into the page’s larger structure. This analogy explains the order of operations. It does not imply that the network explicitly stores words or follows a human reading strategy.

A resolution budget is a reading budget

Try enlarging the abstract patches below. Covering the same image with larger patches yields fewer positions. In the toy grid, reducing positions from 48 to 12 reduces a dense all-pairs attention matrix from 2,304 entries to 144: sixteen times fewer pairs. This is arithmetic about an attention matrix, not a full-model FLOP calculation.

Smaller writing makes the tradeoff concrete. If two nearly identical symbols occupy only a few pixels, removing spatial detail can erase the evidence distinguishing them. A language decoder might complete a plausible phrase despite reading a symbol incorrectly. Plausibility and faithful transcription are different tests.

The released model offers multiple resolution settings and a crop-based mode. Its card specifies 512-, 640-, 1,024-, and 1,280-pixel square modes. The widget is an abstract grid, not a reimplementation of those modes or DeepEncoder’s tokenizer. [3]

Reading back is only the first test

The paper evaluates OCR reconstruction under visual compression. It explicitly leaves general long-context reasoning validation to further work. A system that can reproduce a paragraph has passed a different test from one that can combine facts distributed across many compressed pages. [2]

An independent follow-up compared optical compression with alternative autoencoding approaches. On 1,000-token English Wikipedia contexts, optical reconstruction did not beat keeping recent text at matched input-token budgets for predicting a continuation. A hierarchical text encoder did. These experiments measured next-token prediction, not long-document question answering; other lengths, domains and tasks still need testing. [4]

Ask what survived the bottleneck

A useful experiment would vary the same document’s font size, layout and visual-token budget, then separately score exact transcription and questions requiring distant evidence. Track errors in dates, negations and table alignment, not just whether the answer sounds fluent.

DeepSeek-OCR contributes a concrete architecture and open weights for studying this tradeoff. Its public examples include document-to-Markdown and free OCR prompts. Those are the appropriate starting points; broader claims about replacing a language model’s long-term memory require additional evidence. [3]

For example, keep every word in a two-column table correct but swap the row association between a name and an amount. Character accuracy can remain high while the answer to “how much did this person pay?” becomes wrong. Representation quality must therefore be measured against the task that will consume it, including layout-dependent relationships.

What this tutorial leaves out

  • The input-position bar chart is hypothetical, not a published quality or speed result.
  • The patch widget is an abstract counting exercise, not DeepEncoder tokenization.
  • OCR reconstruction does not establish general long-context reasoning performance.
