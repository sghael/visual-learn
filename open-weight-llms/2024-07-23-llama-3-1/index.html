Llama 3.1 · 8B, 70B, 405B

How training scale, data selection, and a long context work together

A larger model, a longer training run, and a longer conversation are three different things. Llama 3.1 is a useful case study because it expanded all three while keeping a recognizable transformer architecture. The central lesson is how to spend computation at different stages.

5 sections · about 8 minutes · Training

A release larger than its architecture change

Meta released Llama 3.1 on July 23, 2024 in 8B, 70B and 405B sizes, with a 128K-token context and support for eight languages. The announcement also emphasized using the largest model to produce synthetic training data for smaller models. These are release capabilities, not claims that every capability was invented by this family. [1]

A dense transformer uses its ordinary feedforward weights for every token, rather than routing each token through a small subset of experts. Dense models make the parameter count a useful first approximation to per-token computation. They still require optimized implementations and enough memory to execute.

Why retain a familiar architecture? An architecture is only one variable. Improving which documents survive filtering, how often different domains appear, and which answers become post-training examples can change the learned model even when its block diagram looks almost unchanged.

Training and serving favor different choices

The Chinchilla study asks how to divide a fixed training budget between parameter count and training tokens. Its central finding is that both should grow together near its measured compute-efficient frontier. That is a statement about a particular training objective and budget, not a universal rule for the cheapest deployed assistant. [2]

For this illustration, write training work as approximately 6ND, where N is the number of parameters and D the number of training tokens. The result estimates floating-point operations, or FLOPs, for forward and backward computation; it omits important costs such as long-sequence attention. Start with seven billion parameters and one trillion tokens. Moving the slider from seven to fourteen billion parameters halves the token allowance, from one trillion to half a trillion. The slider keeps the product ND constant; it does not predict the resulting quality.

Now imagine the model will answer a million requests. Training is paid once, while generation is paid repeatedly. Spending more training on a smaller model may therefore be attractive even when it is not the minimum-training-compute route to a target score. Serving economics changes the question you are optimizing. [2]

A token count needs a data recipe

The Llama 3 report describes deduplication, filtering, domain mixture experiments, and care when extracting mathematical or programming text from web pages. It also reports grouped-query attention across the family and a larger tokenizer. The contribution is a coordinated training recipe and released checkpoints, rather than one newly invented transformer operation. [3]

Imagine two equally long corpora. One repeats the same copied tutorial a hundred times; the other contains a hundred different explanations with correct worked examples. The raw token count is equal, but the training signal is different. Deduplication can make the nominal budget less redundant; preserving an equation can prevent a parser from turning a useful example into nonsense.

Data quality does not mean deleting every unusual sentence. A filter can remove valuable dialects, difficult domains or minority languages along with noise. A useful research question is therefore which validation tasks improve or deteriorate when the mixture changes, not whether an unspecified quality score rises.

Long context needs more than an allowed length

The report describes extending context in stages rather than merely changing a configuration limit. Long-context training and evaluations are paired with post-training examples that require using distant information. The released 3.1 models are text models; the paper’s vision and speech experiments were not the same public release. [3]

Picture a contract with a definition on page one and an exception near the end. Accepting all the text only establishes that it fits. Answering correctly requires retaining the definition, retrieving the exception and applying both. A successful single-fact retrieval test is useful evidence, but does not establish reliable multi-step reasoning over an entire contract.

The context window is a shared budget for the prompt and generated continuation. This makes it important to distinguish prompt length from generated length. Reading a large prompt can be parallelized extensively. Writing an answer still requires repeated generation steps. Equal total token counts can therefore represent different workloads.

Good demonstrations still need selection

Llama 3.1 uses supervised examples and direct preference optimization in post-training. In DPO, a chosen answer and a rejected answer form a training pair. Relative to a reference model, the objective encourages the chosen answer’s likelihood to increase more than the rejected answer’s. This is an established method described in the DPO paper. [4]

For a toy question, compare “42” with “42, because six groups of seven contain forty-two items.” A preference label can favor the explanation when the user asked to learn. Change the request to “answer with one number,” and the desired preference may reverse. Preference data encodes a context-dependent target.

The practical lesson is to read a model release as a bundle of decisions. Ask separately how it was trained, how its behavior was shaped, what its runtime costs are, and whether an evaluation resembles the task you care about.

What this tutorial leaves out

  • The compute widget is an approximation, not a fitted scaling law or hardware benchmark.
  • The paper’s multimodal research models are not counted as Llama 3.1 released weights.
  • The 128K context budget covers prompt and continuation and does not guarantee reliable use of every detail.
