LLaDA 8B

How to generate text by repeatedly filling blanks

Most familiar language models write one token after another. LLaDA asks a different question: if some words are hidden, can a model predict the missing pieces, then repeat until the text is complete? The model still uses a transformer, but the training objective and generation procedure change.

Train on many amounts of missing text

An autoregressive model learns to predict a next token from its prefix. LLaDA instead corrupts a training sequence by replacing randomly chosen tokens with a mask symbol. A transformer predicts the missing tokens using the visible context on both sides. The masking probability varies over training examples, and the loss is applied to masked positions with the weighting specified in the diffusion objective. [1]

Consider “The small robot reads a book.” Hide “robot” and “book.” The visible words constrain both blanks. Now hide almost everything: the task requires proposing a plausible complete sequence. Learning across masking levels prepares the model for successive stages of generation, from very little visible text to an almost finished response.

This is masked diffusion. The term refers to a corruption-and-reconstruction process over discrete tokens. It does not mean adding Gaussian noise to word meanings in this release, and it does not require abandoning transformer layers.

Several positions can change in a round

For generation, keep the prompt visible and initialize a response region with masks. Predict candidate tokens at the masked positions. A schedule decides which predictions remain visible and which positions stay masked for another round. The project demonstrates different remasking strategies. [2]

In the figure, two positions become visible each round. The scattered order fills separated positions first; the comparison fills from the left. The words and order are scripted so you can isolate the scheduling idea. A real model supplies distributions, and confidence-based selection depends on those predictions.

Notice that a later word can appear before an earlier one. This changes the interface between generation and display. A streaming application may need to revise positions or wait for a block to stabilize. Seeing a final answer early in a denoising run also does not prove that a model internally derived that answer before its explanation.

Parallel predictions still cost repeated passes

Predicting many positions in a single forward pass sounds faster than generating one token. But compare the full bills. An autoregressive decoder can reuse a KV cache for its fixed prefix. A bidirectional denoising step can change the context used at many positions, making ordinary incremental caching harder.

The original repository explicitly notes speed limitations, fixed generation lengths, and a quality tradeoff when the number of denoising steps is reduced. Original LLaDA already supported semi-autoregressive remasking within successive blocks. [2] The repository now links later dynamic-length block-diffusion and caching methods; those later systems are separate advances. [3]

For a toy 128-token response, eight rounds mean eight model passes, but those passes process many positions. Comparing eight with 128 alone does not determine latency. Hardware utilization, prompt length, response length, attention work, cache reuse, and sampling quality all matter. Measure outputs of comparable quality on the same serving stack.

A generative alternative with a specific release history

The public model card identifies the Base and Instruct checkpoints and the custom implementation needed to run them. [4] A base denoiser is not automatically a helpful assistant; instruction tuning changes the training examples while retaining the masked modeling approach.

The paper supports the case that diffusion can acquire important language-model capabilities at this scale. It does not establish that every diffusion model will outperform every autoregressive model. A result on a reversal task, for example, addresses one consequence of generation factorization; it is not a general measure of intelligence.

The dates deserve care. The official repository retrospectively labels the work February 14, 2025, while the official Instruct checkpoint history records a weight-bearing commit on February 20. This folder uses that verifiable artifact date and does not claim to reconstruct when a staged repository became public. [5] Later LLaDA 1.5, MoE, and iLLaDA releases are related developments rather than interchangeable versions of the original checkpoint.

What this tutorial leaves out

  • Folder date is the first recorded weight-bearing commit, not an independently verified public-unveiling timestamp.
  • The unmasking order and sentence are hand-scripted, not generated by a language model.
  • Original LLaDA did not release the complete training data and framework; downloadable weights are a narrower form of openness.
