Quantization-aware training

How a network learns to live on a coarse grid of numbers

A 70-billion-parameter model needs about 140 GB for its weights in 16-bit form and about 35 GB at 4 bits. Rounding the weights after training loses accuracy. Quantization-aware training rounds them during training, so the optimizer can compensate.

Weight memory

A bf16 weight takes two bytes. A packed 4-bit weight takes half a byte, plus a small overhead for the scales that map integers back to real values.With one bf16 scale per group of 128 weights the overhead is 16 bits / 128 = 0.125 bits per weight, so “4-bit” storage is about 4.13 bits in practice. The weights are not the whole bill: activations, the KV cache and the runtime also need memory.

Packed weights also reduce memory traffic, which is what limits speed when a model generates one token at a time. That speed-up needs kernels that unpack the format efficiently; without them the savings are only in storage.

Rounding onto a grid

A symmetric uniform quantizer picks a clipping range [−α, α], divides it into evenly spaced levels, and replaces each value with the nearest level. The spacing between levels is the scale, s = α / qmax.This page uses the signed range −qmax … qmax, which leaves one 4-bit code unused. Many libraries use the full range.

q  = clamp(round(x / s), −q_max, q_max)
x̂ = s · q

What the error looks like

Rounding error is bounded by half a step inside the range. Outside it, clipping error grows without bound, which is why the choice of α trades one error against the other.
