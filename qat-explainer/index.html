Quantization-Aware Training

A 70-billion-parameter model is 140 GB in 16-bit floats. Squeeze each weight into 4 bits and it fits on one GPU, but every weight is now rounded. Quantization-aware training teaches the model to expect that rounding while it is still learning, so the rounded model works as well as the original.

1 · Why shrink a model

Memory is the wall

An LLM is mostly a pile of weights. In bf16, each weight costs 2 bytes, so memory scales with the parameter count. Pick a model size and see where it lands against real GPUs. Notice that the 4-bit bar is what makes a 70B model fit on a single 80 GB card, and what lets an 8B model run on a laptop.

Weight memory only, approximate (parameters × bytes per weight, ignoring group scales). Activations, the KV cache and framework overhead come on top. Reference lines: 16 GB laptop GPU, 24 GB RTX 4090, 80 GB H100.

Fewer bits also means less memory traffic per token, and decoding an LLM is memory-bandwidth-bound, so 4-bit weights are faster too. The catch: 4 bits gives you only 16 distinct values per weight. The whole game is deciding which 16 values, and making the model robust to landing on them.

2 · Quantizing one number

A grid, a scale, and a rounding

Uniform integer quantization is a three-step recipe. Choose a clipping range [−α, α]. Divide it into 2b−1 evenly spaced levels, symmetric about zero; the spacing is the scale s. Then round every real value to the nearest level and store the integer index q. (A signed b-bit integer has one extra code, −2b−1; symmetric schemes leave it unused so that zero sits exactly in the middle.)

qmax = 2b−1−1    s = α / qmax    q = clamp( round( x / s ), −qmax, qmax )    x̂ = s · q

Ticks are the representable levels. Drag x past α and it gets clipped to the edge level. Shrink α and the levels get finer inside the range, at the cost of clipping more of the tail.

Two kinds of error fight each other. Rounding error is at most half a step, so it shrinks when the scale shrinks. Clipping error grows when α is smaller than the values you actually have. Choosing α is a real decision, and every quantization method, PTQ or QAT, has to make it.

This is the symmetric scheme, used for weights. Activations are often asymmetric: the range is [β, α] with a zero-point offset, which spends the levels better on one-sided distributions like the output of a ReLU.

3 · Quantizing a matrix

One outlier ruins the grid

A weight matrix shares a scale across many values. With a single scale per tensor, one unusually large weight forces α up, which spreads the levels out for every other weight in the tensor. Toggle the outlier and watch the error map light up everywhere except at the outlier itself.

12 × 12 slice of a weight matrix. Blue is negative, orange is positive, grey is zero. Hover a cell for its values. Per-row (per-channel) scales let each row pick its own α, so the outlier only hurts its own row. Real 4-bit LLM formats go further and use one scale per group of 32 to 128 weights.

Finer scales fix most of the damage for weights. Activations are harder: some channels in a transformer are consistently 100× larger than the rest, and you cannot pick them off with per-row scales because the outliers sit in the input dimension. That is one reason weight-only 4-bit quantization is common and full 4-bit weights-and-activations is still research.

4 · Rounding in the loop

Post-training vs. quantization-aware

Post-training quantization (PTQ) takes a finished model and rounds it. Fast, no data needed beyond a calibration set, and often fine at 8 bits. At 4 bits and below, the rounding errors compound through dozens of layers and quality drops.

Quantization-aware training (QAT) changes the training loop instead. The forward pass runs on rounded weights, so the loss already includes the damage the rounding does. The backward pass sends gradients to the full-precision master weights, which keep learning. Step through the loop below.

The block labelled fake quantize is the whole idea. It rounds a tensor and immediately dequantizes it, so the tensor is still stored as floats, just floats that happen to sit on the grid. Nothing downstream needs integer kernels; training runs on ordinary GPUs. Only at export time do you keep the integers and throw the master weights away.

5 · The straight-through trick

Rounding has no useful gradient

There is a problem with putting round() inside a network you train by gradient descent. Rounding is a staircase: flat almost everywhere, with a jump at every half-step. Its derivative is zero, so no learning signal would reach the master weights.

The straight-through estimator (STE) is the workaround: in the backward pass, pretend the rounding was the identity function. Gradient with respect to the rounded weight is passed straight through to the master weight. Outside the clipping range the gradient is zeroed, since a clipped weight cannot influence the output by moving further out.

forward: x̂ = s·round(x/s), clipped at ±2

backward: dx̂/dx

Left: the staircase every weight passes through (s = 1 here). Right: the true derivative is 0 everywhere except undefined spikes at the jumps. The STE replaces it with 1 inside the range and 0 where the value is clipped.

Why a fake gradient still works

The master weight is a float. Each step nudges it by a small amount, even when the nudge does not change which level it rounds to. Those nudges accumulate, and eventually the weight crosses a rounding boundary and flips level. The master weight is a memory of gradient evidence that the quantized weight cannot hold on its own.

Under QAT the master weights drift toward the levels, because sitting between two levels is a place where the forward pass is unstable.

Try 2 bits. Only four levels per tensor, so PTQ is often catastrophic, and QAT recovers a lot but not everything: with that few levels, the network genuinely has less capacity. The gap between fp32 and QAT is the true cost of the bit-width; the gap between PTQ and QAT is what training-in-the-loop buys you.

Small details that matter even here, and matter more at LLM scale: the scale is recomputed from the current master weights each step (so here nothing is ever clipped; α is the largest weight), the STE is applied to every weight, and the learning rate decays to zero so the weights settle onto the grid instead of oscillating around it.

7 · Inside a real LLM

What actually gets quantized

Now put the fake-quantize blocks into a transformer layer. Hover each part. The big wins are the linear projections, where nearly all the parameters live. Activations and the KV cache are quantized separately and less aggressively. Norms, softmax and the residual stream usually stay in 16-bit; they are cheap and fragile.

weights, fake-quantized to 4-bit (per-group scales)activations, 8-bit, per-token scalesKV cache, 8-bitkept in bf16

A typical W4A8 (4-bit weights, 8-bit activations) layout. Weight scales are learned or recomputed every step; activation scales are computed per token on the fly at inference. Attention softmax and layer norms stay in bf16.

What changes at LLM scale

You start from a pretrained checkpoint. Nobody pretrains a 70B model with fake-quant from step zero. QAT is a fine-tuning phase: a few thousand steps, a small fraction of pretraining compute.

The teacher is the fp32 model. Instead of next-token labels, the quantized student is trained to match the full-precision model's output distribution (knowledge distillation). The original model is the best possible description of what the quantized one should do, and it needs no labelled data.

Scales are parameters too. Methods like LSQ give each scale its own gradient via the STE, so the model learns how much to clip. The clipping-versus-rounding trade-off from section 2 gets optimized rather than guessed.

Outliers are handled structurally. Per-group weight scales, per-token activation scales, and sometimes rotations that spread outlier channels out before quantizing (as in QuaRot and SpinQuant) are combined with QAT rather than replaced by it.

Rule of thumb. 8-bit: PTQ is enough. 4-bit weights: good PTQ (GPTQ, AWQ) is close, QAT closes the last gap. Below 4 bits, or with 4-bit activations too: QAT is the only thing that works.

9 · Check yourself

Three questions

During QAT, are the weights stored in the optimizer 4-bit or 32-bit?

32-bit (or bf16). The master weights stay full precision throughout training. Only the copy used in the forward pass is rounded, and only at export are the integers kept. Small gradient updates have to accumulate somewhere, and a 4-bit weight cannot hold a change smaller than one level.

Why does the STE zero the gradient outside the clipping range?

If a weight is clipped at α, moving it further out does not change the forward output: it still lands on the edge level. Its true influence on the loss is zero, so passing a gradient through would push it further into a region where nothing it does matters. Zeroing keeps clipped weights from running away. (When scales are learned, that same clipped-weight gradient is redirected into the scale instead, which is how the model learns to widen α.)

Why can QAT beat the best PTQ methods at 2 or 3 bits but not by much at 8 bits?

At 8 bits the rounding error is tiny relative to the weight values, so simply rounding barely moves the loss; there is nothing left to recover. At 2 or 3 bits the levels are coarse and PTQ errors compound layer after layer. QAT lets the whole network co-adapt to the coarse grid, moving weights so that their rounded versions cooperate, which no post-hoc per-layer method can do.
