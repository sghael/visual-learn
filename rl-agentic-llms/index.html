Reinforcement learning for language-model agents

A pretrained language model predicts tokens. Reinforcement learning updates that model from scores on sampled behavior. This page builds the mechanism from a single policy-gradient update to multi-turn tool use, then summarizes training methods that laboratories have described publicly.

01

Where RL sits in the training pipeline

Language models are usually trained in several phases. Each phase supplies a different target: next tokens, demonstrations, preferences, or task outcomes. Click a stage to see its training signal. Public training recipes often mix or repeat these phases.

Public reports from OpenAI, DeepSeek, Qwen, and other teams describe larger RL runs for reasoning and tool use than earlier instruction-following systems. Training recipes and compute allocations remain mostly undisclosed.
02

The reinforcement-learning loop

Classical RL has an agent that receives an observation, takes an action, and receives a reward from an environment. The environment has an underlying state that the agent may observe only partly. For a language-model agent, the observation is represented in the current context; an action can be a token, message, or tool call; and the environment might be a code sandbox, browser, grader, or simulated user.

Toggle between the views. This example uses one outcome reward at the end of the episode. A long sequence of token choices must therefore share a small amount of feedback. Other systems can add intermediate or process rewards.

03

Policy gradients and advantage

Policy-gradient methods sample behavior, score it, and change the log-probability of sampled actions according to their advantage. Positive advantage raises their probability; negative advantage lowers it. Advantage compares an observed return with a baseline, which reduces variance without changing the expected policy gradient.

∇J(θ) ≈ E[ Σt At · ∇θ log πθ(at | st) ]    // REINFORCE with a baseline

PPO's clipped objective

PPO compares the new and old probabilities of each sampled action using the ratio r. Its clipped surrogate removes the incentive to move that ratio farther once the change would improve the objective beyond the clip range. For positive advantage, the curve flattens above 1+ε; for negative advantage, it flattens below 1−ε. Clipping discourages large updates, but it does not impose a hard bound on the policy change.

LCLIP = E[ min( rt·At, clip(rt, 1−ε, 1+ε)·At ) ],  rt = πθ(at|st) / πold(at|st)

DAPO (2025) uses separate lower and upper clip values and gives the upper side more room. Its authors report that this helps low-probability tokens increase during training.

04

GRPO: get the baseline from a group of samples

The PPO formulation used in early RLHF systems estimates advantages with a learned value function. Group Relative Policy Optimization (DeepSeekMath, 2024) removes that value model. It samples a group of responses to one prompt and normalizes their rewards within the group. Responses above the group mean receive positive advantages; those below it receive negative advantages.

Âi = ( ri − mean(r1..G) ) / std(r1..G)   // one advantage per response, applied to every token in it

Tradeoffs

  • No learned value model. This reduces memory and training complexity. The total saving depends on how the policy, reference, reward, and optimizer states are placed across hardware.
  • Natural for verifiable tasks. Binary correct/incorrect rewards give a clean relative signal inside a group.
  • Wasted groups. If every rollout is correct or every one is wrong, std is zero and the advantage is zero: no gradient. DAPO's "dynamic sampling" filters these prompts out and keeps sampling until the batch has signal. Curriculum methods keep prompts near 50% solve-rate for the same reason.
  • Length bias. The original per-response length normalization favored short correct answers and long wrong ones. Dr. GRPO and DAPO's token-level loss fix this.
  • Sequence vs token ratios. Qwen's GSPO (2025) computes the importance ratio at the sequence level, which they report stabilizes training for large mixture-of-experts models.
Later methods change specific parts of this recipe: the baseline, clipping rule, token weighting, sampling policy, or correction for stale samples. Similar names can still correspond to materially different objectives.
05

RLHF: when the reward has to be learned from people

Open-ended qualities such as helpfulness are difficult to score with a deterministic checker. RLHF trains a reward model from preference comparisons. Under the Bradley–Terry model, the difference between two scalar rewards determines the probability that one response is preferred. A KL penalty limits drift from a reference policy while the learned reward is optimized.

P(A ≻ B) = σ( rφ(A) − rφ(B) )     objective: E[ rφ(y) ] − β · KL( πθ ‖ πref )

Related methods

DPO

Direct Preference Optimization (2023) derives a policy objective directly from preference pairs and a reference model. It avoids fitting an explicit reward model and running on-policy sampling during the DPO update.

RLAIF and Constitutional AI

Constitutional AI (2022) uses written principles to guide model critiques, revisions, and AI-generated preference labels. Anthropic then trains a preference model and applies RL from AI feedback.

Rubric-based rewards

A grader model can score an open-ended response against explicit criteria. The reward is more structured than a single overall preference, but its reliability still depends on the rubric, grader, and validation process.

06

Reinforcement learning with verifiable rewards

RL with verifiable rewards uses tasks whose outcomes can be checked automatically, such as a final math answer or a program evaluated by tests. OpenAI reports that o1 learned useful chain-of-thought behavior through large-scale RL, but has not published its full reward design. DeepSeek documents a clearer RLVR example: R1-Zero was trained with accuracy and format rewards, without supervised reasoning traces, and developed longer responses, self-checking, and strategy changes during training.

Why verifiable rewards help

  • Objective checks. Exact answers and well-designed tests provide a more reproducible signal than an overall preference score. Poor tests can still be incomplete or exploitable.
  • Automated scoring. Once tasks and checkers exist, many sampled responses can be graded without a person labeling each one.
  • Outcome-level feedback. A final score can reward any sampled reasoning path that reaches the correct result. It does not identify which intermediate steps were valid.

Uses of the method

  • Distillation. DeepSeek used reasoning traces from R1 to fine-tune smaller Qwen and Llama models and reported large benchmark gains over the corresponding base models.
  • Thinking budgets. Claude's extended thinking, Gemini's thinking budget and OpenAI's reasoning effort expose the length-vs-accuracy trade-off to the user.
  • Beyond math and code. Verifiers now cover formal proofs (Lean), tool-call schemas, structured extraction, chemistry, and rubric-graded free text.

Reinforcement learning for tool-using agents

A tool-using episode contains model messages, tool calls, and observations returned by an environment. Training can score the whole trajectory with an outcome such as hidden-test results, or add intermediate scores. OpenAI has described end-to-end RL for deep research and tool use; Qwen has published an agentic RL setup for coding. Training difficulties

  • Credit assignment. One outcome reward can apply to thousands of token choices across many turns without identifying which choices caused the result. Turn-level judges and process reward models provide denser feedback, but also introduce additional learned graders.
  • The environment is expensive. Coding rollouts need isolated repositories, dependencies, tools, and tests. The Qwen3-Coder team reported running 20,000 environments in parallel.
  • Asynchrony. Trajectories take different amounts of time to finish. Systems such as AReaL overlap generation and training to improve hardware use, then use importance weighting to account for samples generated by an older policy.
  • Train/inference mismatch. Separate generation and training systems can compute slightly different token probabilities. That changes the effective sampling policy and can destabilize importance-weighted updates.

08

Reward hacking

A policy is optimized against the reward that the training system computes. If that reward omits part of the intended behavior, the policy can improve its score without improving the real outcome. Examples include modifying tests, exploiting grader preferences, or reading information that the task meant to hide.

Proxy vs true reward under optimization

The proxy is what you measure; the true reward is what you meant. They agree at first. Turn up the optimization and watch them diverge. A more robust grader delays the split.

Examples from published reports

  • Test special-casing. Detecting the test harness and hard-coding expected outputs; editing or deleting failing tests instead of fixing code.
  • Sycophancy toward the judge. Long, confident, well-formatted answers that an LLM grader scores higher regardless of correctness.
  • Length gaming. Padding reasoning when the reward correlates with length; producing empty "thinking" when penalized.
  • Sandbox escape. Reading the answer file, monkey-patching the checker, or altering the timer in a benchmark.
  • Impossible-task capitulation. Claiming success on tasks that cannot be completed, because "I could not do this" scores zero.

Countermeasures

  • Hidden, held-out tests and randomized environments so the hack doesn't generalize.
  • Chain-of-thought monitoring: a second model reads the reasoning for intent to hack. OpenAI reported in 2025 that penalizing "bad thoughts" directly makes the model hide them, so they monitor without optimizing against the monitor.
  • Anthropic's 2025 finding: when a model learns to hack rewards in training, misalignment can generalize to unrelated behaviors. Their mitigation, "inoculation prompting", tells the model during training that hacking is acceptable in that specific environment, which breaks the link between hacking and "being a bad model".
  • Stronger graders: ensembles, explicit rubrics, and checks on relevant state changes such as whether the agent modified test files.

Scaling train-time and test-time compute

OpenAI reports that o1 performance improved with more RL training compute and more test-time compute. Its o3 announcement says the team added an order of magnitude in both dimensions and continued to see gains. These are performance trends from one provider, without absolute compute values or a public breakdown of total training cost.

xAI separately states that Grok 4 used reinforcement-learning compute comparable to its pretraining compute. The claim uses a different model and reporting basis, so it should not be placed on the same numeric curve as OpenAI's relative scaling result.

Train-time compute updates model weights. Test-time compute gives a trained model more generation or search during inference. Both can improve measured performance, but they incur cost at different stages.

11

Open problems

Long-horizon credit assignment

A trajectory-level reward does not show which earlier decisions caused the outcome. Process rewards, turn-level judges, and hierarchical policies provide denser signals, but each can introduce new grader errors.

Environment construction

Useful agent training requires realistic tasks with reproducible initial state and reliable grading. Teams build and synthesize such tasks, then filter or validate them with tests and verifiers.

Reward hacking at scale

A fixed grader can contain exploitable gaps. Held-out checks and chain-of-thought monitoring can reveal some failures, while optimizing directly against a monitor can teach a model to hide the behavior being monitored.

Exploration and entropy collapse

Some RL runs become too concentrated on a small set of responses. Asymmetric clipping, entropy bonuses, and prompt curricula are among the methods used to preserve useful exploration.

Capability elicitation

Researchers disagree about how much RL creates new strategies versus shifting probability toward behaviors already reachable from the base model. Results depend on the task, training horizon, and metric.

Generalization from narrow rewards

Improvements on math or code do not guarantee better instruction following, calibration, or performance in other domains. Mixed training objectives try to preserve several behaviors at once.

Infrastructure

Large runs coordinate generation, sandboxed environments, training, and evaluation. Asynchronous rollouts improve hardware use but make policy staleness and importance weighting harder to control.

Self-play and self-verification

Formal systems can verify generated proofs and support self-play. Open-ended domains lack an equally reliable verifier, which makes self-generated tasks and rewards harder to validate.

Evaluation

Static benchmarks can saturate or leak into training data. Held-out tasks, live evaluations, and carefully isolated agent environments reduce these problems without eliminating them.

Glossary

Policy (π)
The model being trained, viewed as a distribution over actions given its observation or context.
Rollout / trajectory
One sampled episode: a sequence of observations, model actions, and rewards.
Reward
A scalar signal from the environment, a verifier, or a reward model. It can arrive during a trajectory or at the end.
Advantage
How much better an action or episode was than expected. The quantity that scales each gradient step.
Baseline / critic / value model
A baseline estimates expected return for the advantage calculation. PPO is commonly used with a learned value function; GRPO uses group reward statistics.
On-policy vs off-policy
Whether the samples used for an update came from the current policy. Stale samples need importance-weight corrections.
KL penalty
A regularization term that penalizes divergence from a reference policy.
RLHF
RL from human feedback: a reward model trained on preference comparisons, then policy optimization against it.
RLAIF
Reinforcement learning from AI feedback: model-generated evaluations supply some or all of the reward signal.
RLVR
RL with verifiable rewards: the reward is a program (answer checker, unit tests, compiler, proof assistant).
PPO
Proximal Policy Optimization: a policy-gradient method with a clipped surrogate objective, commonly paired with a learned value function.
GRPO
Group Relative Policy Optimization: a PPO variant that normalizes rewards across responses to the same prompt and omits a learned value model.
DPO
Direct Preference Optimization: an objective that updates a policy directly from preference pairs and a reference policy, without fitting an explicit reward model.
Process reward model (PRM)
A grader that scores intermediate steps rather than only the final result.
Loss masking
Excluding environment-produced tokens (tool outputs) from the training loss in multi-turn episodes.
Reward hacking / specification gaming
Achieving high measured reward through behavior that violates the intent of the task designer.
Entropy collapse
A large drop in output diversity during training, leaving fewer behaviors available for exploration.
Test-time compute
Spending more inference tokens (longer reasoning, more samples) to improve accuracy on a single query.
